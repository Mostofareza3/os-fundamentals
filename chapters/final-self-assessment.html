উপসংহার

Final Self-Assessment

৪৭টা প্রশ্ন। Multiple choice না, "নিজের ভাষায় বলো" ধাঁচের। প্রতিটার উত্তর বইয়ের ভেতরেই আছে, বন্ধনীতে লেখা chapter-এ। লক্ষ্য একটাই: "term চিনি" আর "বুঝি"-র পার্থক্য ধরা।

কীভাবে ব্যবহার করবে: বই বন্ধ রেখে প্রতিটা প্রশ্নের উত্তর লেখো বা জোরে বলো, যেন কাউকে বোঝাচ্ছ। যেখানে সংখ্যা বা experiment-এর কথা আছে, সেটা মনে করে বলতে পারলে সবচেয়ে ভালো, কারণ তখন বোঝা যায় তুমি ব্যাপারটা দেখেছ, শুধু পড়োনি। আটকে গেলে বন্ধনীর chapter-এ ফিরে যাও, আর পারলে সেই chapter-এর experiment-টা আবার চালাও।

বড় ছবি (Part 1)

  1. OS না থাকলে কোন তিনটা সমস্যা হতো? Abstraction আর resource management এদের কোনটা কীভাবে মেটায়? (Ch 1)
  2. নিয়ম রক্ষার পাহারা software-এ না রেখে CPU-র hardware-এ, মানে user mode আর kernel mode-এ, রাখতে হলো কেন? System call-এ program নিজে kernel-এর কোন code-এ ঢুকবে সেটা বাছতে পারে না কেন? (Ch 1, 31)
  3. একটা readFileSync-এর পুরো যাত্রা বলো: CPU, kernel, driver, SSD, interrupt — কে কখন কী করে, আর SSD যখন data আনছে তখন তোমার process কী করছে? (Ch 2)

Program থেকে process (Part 2)

  1. Program আর process-এর পার্থক্য কী? একই program-এর দুই process একে অন্যের data ছুঁতে পারে না কেন? (Ch 3, 9)
  2. File descriptor কী, কার table-এ থাকে, আর path-এর বদলে নম্বর দিয়ে কাজ করার সুবিধা কী? (Ch 3, 21)
  3. execve-র পর process-এর প্রথম instruction তোমার code-এর না কেন? Kernel-এর loader আর dynamic linker কে কোন কাজ করে? (Ch 4, 34)
  4. Address space-এর region-গুলো কী কী, কোনটার permission কী, আর code region read-only হওয়ায় কী লাভ? (Ch 5)
  5. Stack frame কোন সমস্যার সমাধান করে? Stack-এ জায়গা নেওয়া এত সস্তা কেন, আর stack overflow কেন হয়? (Ch 5)
  6. কোন data stack-এ রাখা যায় না, আর তাই heap কেন লাগে? Closure-এর variable-এর scope শেষ হয়েও lifetime চলে কীভাবে? GC থাকার পরেও Node server-এ memory leak হয় কীভাবে? (Ch 6)

Memory (Part 3)

  1. Latency আর bandwidth: একই RAM থেকে সেকেন্ডে ~৫৮ GB আর ~০.০৩ GB, দুটোই কীভাবে সত্যি? (Ch 7)
  2. Cache line কী? একই যোগফল এলোমেলো ক্রমে পড়লে দশ গুণ ধীর কেন, আর prefetcher কখন সাহায্য করতে পারে না? (Ch 8)
  3. প্রতিটা process-কে নিজস্ব virtual address space দেওয়ার তিনটা কারণ। Page, frame, page table আর TLB — কে কী কাজ করে? (Ch 9)
  4. Page fault সবসময় error না — একটা "ভালো" page fault-এর উদাহরণ দাও। Minor আর major fault-এর দামে এত তফাত কেন? (Ch 9, 10, 34)
  5. Overcommit কী, আর তার শেষ পরিণতি OOM killer। Exit code ১৩৭ আর "JavaScript heap out of memory" — দুই মৃত্যুর পার্থক্য কী? (Ch 10, 36)
  6. DMA না থাকলে বড় I/O-তে CPU-র কী দশা হতো? DMA-র পরেও কোন copy বাকি থাকে? (Ch 11)

CPU (Part 4)

  1. CPU-র কাছে "program চলছে" মানে কী? তোমার if কীভাবে একটা তুলনা আর একটা লাফ হয়? শুধু GHz দিয়ে CPU তুলনা করা ভুল কেন? (Ch 4, 12)
  2. একটা বড় cache-এর বদলে কয়েক স্তর কেন? Temporal আর spatial locality — নিজের code থেকে একটা করে উদাহরণ। Linked list কেন array-র কাছে হারে? (Ch 13)
  3. False sharing কী? দুই worker একে অন্যের data না ছুঁয়েও কীভাবে পরস্পরকে ধীর করে? (Ch 13)
  4. Pipelining latency বাড়ায় না throughput? Branch prediction ভুল হলে কী দাম দিতে হয়? (Ch 14)
  5. ১২ worker-এ ১২ গুণ না হয়ে ৮ গুণ দ্রুত কেন, আর ২৪-এ উল্টো ফল কেন? (Ch 14, 17, 40)

Process আর thread (Part 5)

  1. Running, ready আর blocked — কে CPU চায়, কে চায় না? Scheduler কোন কোন মুহূর্তে চলে? (Ch 15)
  2. fork() "দুইবার ফেরে" মানে কী? fork আর exec আলাদা হওয়ায় shell-এর redirect কীভাবে সম্ভব হয়? Zombie কী, আর কে তাকে সরায়? (Ch 15, 37)
  3. Process আর thread-এর আসল পার্থক্য ওজনে না, address space-এ — ব্যাখ্যা করো। Linux-এ দুটোই কীভাবে একই clone দিয়ে তৈরি হয়? (Ch 16)
  4. Context switch-এ কী save আর restore হয়, আর লুকানো দামটা কোথায়? Voluntary আর involuntary switch-এর সংখ্যা কী বলে? (Ch 17)
  5. counter++ কীভাবে race condition বানায়? JS-এ একটাই thread থাকার পরেও race condition সম্ভব — একটা উদাহরণ দাও। (Ch 18)
  6. কাজটা CPU-bound না I/O-bound, time দিয়ে কীভাবে বুঝবে? কোন কাজে event loop, কোন কাজে worker, আর libuv-এর thread pool-এর সীমা কী? (Ch 19, 39)

Storage (Part 6)

  1. Latency, throughput আর IOPS আলাদা মাপ কেন? একই SSD-তে একসাথে অনেক অনুরোধ পাঠালে IOPS প্রায় নয় গুণ হয় কেন? (Ch 20, 40)
  2. write() ফিরে আসার পরেও data হারাতে পারে — পুরো ঘটনাটা বলো। Crash-safe লেখার নিয়ম কী, আর rename-এর আগে ও পরে fsync কেন? (Ch 21, 23)
  3. Inode-এ file-এর নাম থাকে না — তাহলে নাম কোথায় থাকে? df বলছে disk ভরা অথচ du কিছু পাচ্ছে না — কী ঘটেছে? (Ch 22)
  4. Page cache কী, সব process-এর জন্য একটাই কেন, আর benchmark-এ cold আর warm আলাদা মাপতে হয় কেন? Container-এর memory হিসাবে page cache কীভাবে ঢোকে? (Ch 23)
  5. File-এ epoll চলে না কেন, আর তাই Node file-এর কাজ কোথায় পাঠায়? Durability কেনার উপায়গুলোর (fsync, fdatasync, O_SYNC, মাঝে মাঝে fsync) দাম কেন আলাদা? (Ch 24)

Network (Part 7)

  1. Socket কী, আর সেটা একটা fd হওয়ায় কী সুবিধা? এক port-এ হাজার connection কীভাবে আলাদা থাকে? (Ch 25)
  2. TCP "connection" physically কোথায় থাকে? Handshake কে করে, আর SYN queue বা accept queue ভরলে কী উপসর্গ দেখা যায়? (Ch 26, 38)
  3. "TCP byte-এর স্রোত, message না" — এর মানে কী, আর framing কেন তোমার দায়িত্ব? socket.write() false দিলে কী করবে? (Ch 27)
  4. Nagle আর delayed ACK মিলে ~৪২ ms কীভাবে বানায়? এই bug Mac-এ লুকিয়ে থেকে Linux-এ load আসার পর বেরোয় কেন? (Ch 27, 38)
  5. Thread-per-connection কোথায় ভাঙে, আর epoll কী বদলে দেয়? Event loop-এ ভারী sync কাজ চললে kernel-এর ভেতরে আর বাইরে কী ঘটে? (Ch 28, 29, 39)
  6. ECONNREFUSED, ETIMEDOUT, ECONNRESET, EPIPE, EMFILE — প্রতিটার পেছনে kernel-এ বা network-এ আসলে কী ঘটেছে? (Ch 30)

Kernel-এর সীমানা, আর executable (Part 8–9)

  1. Kernel-এ ঢোকার তিন দরজা কী কী, আর signal কীভাবে উল্টো দিকে খবর আনে? root হয়েও process user mode-এ থাকে কেন? (Ch 31)
  2. একটা syscall-এর দাম কোথা থেকে আসে? কখন সেই দাম তুচ্ছ, কখন সেটাই মূল খরচ? vDSO কী বাঁচায়? (Ch 32)
  3. Static আর dynamic linking: binary-র মাপ, RAM-এ ভাগাভাগি, security fix — কোনটায় কে জেতে? Node-এর .node file আসলে কী? (Ch 33)
  4. "File আছে, তবু not found" — কোন তিনটা আলাদা file-এর অভাবে এই ENOENT আসতে পারে? Load মানে copy না কেন? (Ch 34)

Virtualization আর container (Part 10)

  1. VM-এর guest kernel kernel mode-এ চলেও আসল hardware ছুঁতে পারে না কেন? Steal time কী, আর cloud-এ কখন সেটা দেখবে? (Ch 35)
  2. Container VM না কেন — namespace, cgroup, capability আর seccomp দিয়ে ব্যাখ্যা করো। Container-এ Node চালানোর দুটো ফাঁদ কী? (Ch 36)

সব একসাথে (Part 11–12)

  1. node hello.js-এর ১৩ ms কোথায় কোথায় যায়, আর তোমার লেখা লাইন তার কতটুকু? strace কোন জিনিসগুলো দেখতে পায় না? (Ch 37)
  2. একটা ধীর service-এর সামনে প্রশ্নের ক্রম কী? time-এর তিন সংখ্যা থেকে শুরু করে USE method পর্যন্ত বলো। CPU মাত্র ১০% দেখালেও সমস্যা CPU-তে হতে পারে কীভাবে? (Ch 39)
  3. Utilization ৮০% থেকে ৯০%-এ গেলে latency দ্বিগুণ কেন? Little's law দিয়ে একটা connection pool-এর আকার ঠিক করো। Latency-র লক্ষ্য গড়ে না লিখে P99-এ কেন? (Ch 40)
  4. শেষটা বড়: browser-এ একটা button চাপা থেকে API response ফেরা পর্যন্ত পুরো গল্প — CPU, memory, socket, kernel, syscall, cache, scheduler সবাইকে চরিত্র বানিয়ে — নিজের ভাষায় বলো। (Ch 38, আর আসলে পুরো বই)
এরপর কী

এই বই ইচ্ছে করেই অনেক কিছু বাদ দিয়েছে: scheduling algorithm-এর তত্ত্ব, filesystem-এর ভেতরের data structure, kernel-এর নিজের code লেখা। সবচেয়ে ভালো পরের ধাপ হলো নিজের production app-এর নিচে তাকানো: strace -c, vmstat 1, event loop delay-এর metric, আর Chapter 37-এর watch.js-এর মতো process.resourceUsage()। তত্ত্বে আরও গভীরে যেতে চাইলে Operating Systems: Three Easy Pieces (Arpaci-Dusseau)। মাপজোখের জন্য Brendan Gregg-এর Systems Performance। আর প্রতিটা system call-এর আসল সংজ্ঞা আছে Linux-এর man page-এ (man 2 read)। বইয়ের মূলমন্ত্র মনে রেখো: Depth > Breadth, Mental Model > Memorization, আর অনুমানের আগে মাপ।
