The Operating Systems Mental Model

পুরো বই, এক ছবিতে — তারপর সুতোগুলোর জোড়া।

        Application (তোমার code)
        Runtime / Libraries (V8, libc, JVM)
┌─────────────  USER SPACE  ─────────────┐
│  process memory: code · data · heap · stack  │
└──────────────────┬─────────────────────┘
          system calls (একমাত্র দরজা)
┌────────────────  KERNEL  ──────────────┐
│ Process Mgmt   — scheduler, fork, states │
│ Memory Mgmt    — page tables, page cache │
│ File System    — VFS, ext4, inodes       │
│ Network Stack  — sockets, TCP/IP, queues │
│ Device Drivers — disk, NIC (DMA, IRQ)    │
└──────────────────┬─────────────────────┘
                   ↓
        Hardware:  CPU (+cache) · RAM · Storage · Network

সুতোগুলো

  • সব রাস্তার এক প্যাটার্ন: চাওয়া (নীল) → syscall → kernel-এর স্তর → hardware → ফেরা। File, network, memory — গল্প একটাই, চরিত্র আলাদা।
  • Illusion স্তরে স্তরে: Virtual memory প্রতিটা process-কে "memory তোমার একার" বলে; scheduler বলে "CPU তোমার একার"; TCP বলে "নির্ভরযোগ্য stream আছে"; namespace বলে "machine-টা তোমার একার"; hypervisor বলে "hardware তোমার একার"। OS মানে সুশৃঙ্খল মিথ্যার স্থাপত্য — যে মিথ্যাগুলো আমাদের সরল code লিখতে দেয়।
  • যেখানেই speed-ফারাক, সেখানেই cache/buffer: CPU cache, TLB, page cache, socket buffers, তোমার Redis — এক pattern-এর পাঁচ তলা।
  • সবকিছুর দাম আছে: syscall-এর boundary cost, context switch-এর cache-দূষণ, page fault-এর disk-যাত্রা, lock-এর লাইন। Engineering মানে এই দামগুলো জেনে খরচ করা।

আর সেই final goal-টা মিলিয়ে দেখো: এখন একটা running application-এর দিকে তাকালে তোমার চোখে ভাসা উচিত — process আর তার address space, stack-এ ওঠানামা করা frames, heap-এ জন্মানো objects, cache-এ hit-miss-এর জুয়া, boundary পেরোনো syscalls, kernel-এর queue আর buffer, disk আর NIC-এর DMA, আর scheduler-এর অদৃশ্য কাঁচি। যদি ভাসে — বইটা কাজ করেছে।
