PART 2 · FROM PROGRAM TO PROCESS

Chapter 3 — Program vs Process

এই পার্থক্যটা পরিষ্কার না হলে সামনের অর্ধেক বই ঝাপসা লাগবে। তাই আলাদা করে একটা পুরো chapter।

Program: disk-এ শুয়ে থাকা file

Program হলো একটা executable file — disk-এ পড়ে থাকা bytes। এর ভিতরে আছে machine instructions (CPU-র ভাষায় compiled code), কিছু initial data, আর metadata (কোথা থেকে execution শুরু হবে ইত্যাদি)। Linux-এ এই file format-এর নাম ELF। গুরুত্বপূর্ণ কথা: program একটা passive জিনিস। /usr/bin/node file-টা disk-এ পড়ে আছে — কিছুই করছে না।

Process: সেই file-এর একটা running instance

তুমি যখন node server.js চালাও, OS ওই executable-টা নিয়ে একটা process বানায়। Process মানে শুধু "চলছে" না — process মানে OS একগাদা জিনিস তৈরি করে দিয়েছে:

  • একটা PID (Process ID) — kernel-এর খাতায় unique নাম্বার
  • নিজস্ব virtual address space — process-এর নিজের "private" memory জগৎ (Chapter 9)
  • Memory-তে load হওয়া code, data, heap আর stack (Chapter 5)
  • CPU state — registers, program counter (এখন কোন instruction-এ আছে)
  • Open file/socket-দের list — file descriptor table
  • Kernel-এর bookkeeping — state (running/waiting), owner, parent কে, ইত্যাদি
MENTAL MODEL

Program = recipe (কাগজে লেখা, passive)। Process = রান্না চলছে (চুলা জ্বলছে, উপকরণ কাটা হচ্ছে, নির্দিষ্ট state আছে)। একই recipe থেকে একসাথে দুই হাঁড়িতে রান্না চলতে পারে — দুইটা আলাদা process, আলাদা state, আলাদা হাঁড়ি (memory)।

একই program, দুইটা process

দুইটা terminal খুলে দুই জায়গায় node চালাও। Executable file একটাই, কিন্তু process দুইটা — আলাদা PID, আলাদা memory, আলাদা variables। একটাতে crash হলে আরেকটার কিছু হয় না। এটাই isolation — OS-এর অন্যতম প্রধান উপহার। তোমার Chrome-এর প্রতিটা tab আলাদা process রাখার পিছনেও এই একই logic — এক tab মরলে বাকিরা বাঁচে।

COMMON MISCONCEPTION

"Process = program in execution" — শুরুর জন্য ঠিক আছে, কিন্তু অসম্পূর্ণ। Process-এর নিজস্ব identity (PID), নিজস্ব address space, নিজস্ব resources আছে। শুধু "চলমান code" না — বরং code + memory + state + kernel bookkeeping-এর একটা পুরো package। আর সামনে দেখবে, একটা process-এ একাধিক thread-ও থাকতে পারে — তখন "in execution" অংশটা আসলে thread-এর কাজ।

EXPERIMENT

দুইটা terminal-এ চালাও: sleep 300 (দুই জায়গায়)। তৃতীয় terminal-এ: ps aux | grep sleep। দেখবে একই program (/bin/sleep) কিন্তু দুইটা আলাদা PID। Linux হলে ls /proc/<PID>/ চালিয়ে দেখো — প্রতিটা process-এর জন্য kernel কত কিছু track করে।
