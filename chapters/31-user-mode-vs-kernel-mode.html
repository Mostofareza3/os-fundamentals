PART 8 · USER SPACE AND KERNEL SPACE

Chapter 31 — User Mode vs Kernel Mode

এই বইয়ের নীল-আর-amber রেখাটা এবার পুরো আলোয়।

Privilege: hardware-এ খোদাই করা নিয়ম

এটা কোনো software convention না — CPU নিজে দুই (বা ততোধিক) privilege level-এ চলে। Kernel mode-এ সব instruction, সব memory, সব device বৈধ। User mode-এ dangerous instruction (device-এ কথা বলা, page table বদলানো, interrupt বন্ধ করা) দিলে CPU নিজেই আটকে দিয়ে kernel-কে ডেকে দেয়। মানে যত বড় bug-ই লেখো, তোমার process সরাসরি hardware নাড়াতে পারবে না — দারোয়ান silicon-এ বসানো।

এখানে একটা জিনিস আলাদা করে রাখা দরকার, কারণ দুটো প্রহরীকে প্রায়ই এক ভাবা হয়। Privilege level আটকায় privileged instruction আর সরাসরি device access। কিন্তু "অন্য process-এর memory পড়তে পারবে না" — এটা privilege level-এর কাজ না, এটা per-process page table-এর কাজ (Chapter 9)। B-র data-র কোনো entry A-র page table-এ নেই, তাই A-র কাছে ওই address-টা উচ্চারণযোগ্যই না। দুটো ভিন্ন mechanism, দুটো ভিন্ন কাজ।

আর সীমানাগুলো পরম নয়। ইচ্ছাকৃত ফাঁক আছে (shared memory, ptrace, /proc/<pid>/mem — debugger এভাবেই কাজ করে), আর অনিচ্ছাকৃত ফাঁকও ধরা পড়েছে: Meltdown (২০১৮) user mode থেকেই kernel memory পড়ে ফেলেছিল, কোনো privileged instruction ছাড়া — speculative execution-এর পার্শ্বপ্রতিক্রিয়া মেপে। এজন্যই আজকের kernel user আর kernel-এর page table আলাদা রাখে (KPTI), আর এজন্যই syscall আগের চেয়ে দামি (Chapter 32)।

কেন এত কড়াকড়ি? কারণ machine-টা shared। শত process, ভিন্ন user, আধা-বিশ্বাসী code — এদের মাঝে বিশ্বাসের সীমানা টানতেই হয়। Protection ছাড়া এক process-এর ভুল মানে পুরো machine-এর মৃত্যু (পুরনো DOS-যুগের বাস্তবতা)।

দুটো সূক্ষ্মতা লক্ষ করো: (১) ঢোকার জায়গাটা kernel-এর নির্ধারিত — user code "kernel mode-এ গিয়ে নিজের ইচ্ছামতো code" চালাতে পারে না; পারে শুধু kernel-এর menu থেকে order দিতে। (২) Kernel প্রতিটা argument সন্দেহের চোখে দেখে — user-এর দেওয়া pointer, সংখ্যা, সবকিছু validate হয়। এই অবিশ্বাসটাই security।

Mode বদলের আরও দুই দরজা আছে, ফাউ হিসেবে জেনে রাখো: interrupt (hardware-এর ডাক — NIC-এর "data এসেছে", timer-এর tick) আর exception/fault (তোমার code-এর কাণ্ড — page fault, zero-division)। তিন দরজাই এক জায়গায় নামে: kernel-এর নিয়ন্ত্রিত entry point।

MENTAL MODEL

Kernel হলো ব্যাংকের vault-এর কর্মকর্তা। তুমি (user process) vault-এ ঢুকতে পারো না — কাউন্টারে (syscall interface) slip জমা দাও, কর্মকর্তা ভিতরে গিয়ে কাজ করে ফলাফল আনে। Slip-এ যা-ই লেখো, কর্মকর্তা যাচাই করেই কাজ করবে। ব্যবস্থাটা একটু আনুষ্ঠানিক, তাই একটু ধীর — কিন্তু এজন্যই ব্যাংক লুট হয় না।
