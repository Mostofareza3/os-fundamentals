PART 4 · CPU

Chapter 14 — Pipelining আর Parallelism

CPU একটা instruction শেষ করে পরেরটা ধরে না — কেন এবং তার মানে কী।

Pipeline: assembly line-এর কৌশল

Chapter 12-র সেই fetch → decode → execute → memory → writeback ধাপগুলো ভাবো একটা garment factory-র line হিসেবে। এক instruction যখন decode হচ্ছে, পরেরটা তখন fetch হতে পারে — ধাপগুলো তো আলাদা যন্ত্রাংশে চলে। এটাই pipelining: এক মুহূর্তে pipeline-এর ভিতরে একাধিক instruction, প্রত্যেকে আলাদা stage-এ। ফলে প্রতিটা instruction-এর নিজের সময় না কমলেও প্রতি cycle-এ একটা করে instruction "বের হয়ে আসে"।

Pipeline-এর শত্রু হলো branch — if/else, loop-এর শর্ত। পরের instruction কোনটা, তা তো শর্তের result-এর আগে জানা যায় না! CPU তখন অনুমান করে (branch prediction) আগেভাগে কাজ চালিয়ে যায়; অনুমান ভুল হলে pipeline-এর আধখাওয়া কাজ ফেলে দিতে হয়। এজন্যই খুব unpredictable branching-ওয়ালা code (যেমন unsorted data-র উপর শর্ত) মাঝে মাঝে আশ্চর্যরকম ধীর হয়।

Parallelism-এর স্তরগুলো

  • Pipeline (এক core-এর ভিতরে): ধাপ overlap — উপরে দেখলাম।
  • Multiple cores: সত্যিকারের একসাথে একাধিক instruction stream। ৮ core = ৮টা process/thread আক্ষরিকভাবেই simultaneously।
  • SMT / Hyper-threading: এক physical core দুইটা "hardware thread" সাজে — এক thread memory-র জন্য wait করলে core-এর অলস যন্ত্রাংশ আরেক thread চালায়। দুই core-এর সমান না, কিন্তু utilization বাড়ে। এজন্যই ৪-core laptop-এ nproc ৮ দেখাতে পারে।
Side note: RISC vs CISC, 32-bit vs 64-bit

RISC vs CISC: Instruction set design-এর দুই দর্শন — ছোট-সরল instruction (RISC: ARM, তোমার M-series Mac) বনাম জটিল-শক্তিশালী instruction (CISC: x86)। আজকাল ভিতরের বাস্তবায়ন অনেকটা মিলে গেছে; app developer হিসেবে মূল takeaway: আলাদা instruction set মানে আলাদা machine code — এজন্যই ARM Mac-এ x86 binary সরাসরি চলে না (Rosetta translate করে)।

32-bit vs 64-bit: মূলত address-এর size। 32-bit-এ virtual address space সর্বোচ্চ 4GB — আধুনিক workload-এর জন্য হাস্যকর ছোট; 64-bit-এ কার্যত সীমাহীন। Registers-ও চওড়া হয়। ব্যস, এটুকুই দরকার।

ENGINEERING TAKEAWAY

CPU নিজে ভিতরে ভিতরে প্রচণ্ড parallel — কিন্তু এক core-এ তোমার single-threaded JS যতই optimize করো, বাকি ৭টা core বসে থাকবে। Multi-core কাজে লাগাতে হলে process/thread level-এ parallelism আনতে হয় — সেই গল্প Part 5-এ।
