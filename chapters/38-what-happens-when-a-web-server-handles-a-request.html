PART 11 · PUTTING EVERYTHING TOGETHER

Chapter 38 — একটা Web Server-এ Request এলে কী ঘটে?

দ্বিতীয় মহাসংযোগ — এবং তোমার প্রতিদিনের কাজের সবচেয়ে কাছের গল্পটা। ধরি: Node/Express API, Postgres, এক user browser-এ চাপ দিলো।

  1. Browser-এর দিক: DNS, তারপর TCP handshake — SYN উড়ে এলো তোমার server-এ। তোমার Node process টেরও পেলো না — kernel একাই SYN queue → handshake → accept queue সামলালো। [Ch 26]
  2. Event loop-এর ঘুম ভাঙলো: Node epoll_wait-এ ঘুমিয়ে ছিল; listening fd ready → জাগলো → accept() → নতুন connection fd, non-blocking করে epoll-এ ADD। [Ch 29, 25]
  3. Request এলো: NIC → DMA → interrupt → kernel TCP: চার-টুপল মিলিয়ে সঠিক socket-এর receive buffer-এ HTTP bytes → epoll-এ সেই fd ready। Node read() করলো, HTTP parse হলো, তোমার route handler ডাক পেলো — এতক্ষণে, প্রথমবারের মতো, তোমার লেখা code মঞ্চে। [Ch 27, 29]
  4. Handler-এ await db.query(...): Postgres-এর দিকের socket-এ query write() (send buffer-এ জমা) — আর ব্যস, অপেক্ষা নয়: callback নথিভুক্ত করে event loop পরের event ধরলো। ওই এক thread এই ফাঁকে অন্য দশটা request-এর টুকরো এগোলো — এটাই সেই waiter-এর জাদু। [Ch 28-29, 19]
  5. ওদিকে Postgres (আলাদা process!): নিজের socket-এ query পেলো, plan করলো, data চাইলো — তার নিজের page cache-জগৎ, ভাগ্য খারাপে disk: block layer → driver → DMA। ফলাফল socket-এ ফেরত write()। [Ch 21, 23, 20]
  6. ফলাফল ফিরলো: আবার NIC → interrupt → TCP → Node-এর সেই fd ready → event loop জাগলো → তোমার await-এর পরের লাইন চললো। Response JSON বানানো — এটুকু খাঁটি CPU কাজ: V8-এর machine code, cache hit/miss, heap-এ object জন্ম (পরে GC-র খোরাক)। [Ch 12-13, 6]
  7. Response রওনা: res.json() → শেষমেশ socket-এ write() → send buffer → TCP segment → IP → NIC → ইন্টারনেটের ওপারে browser-এর kernel → তার receive buffer → browser-এর epoll-জাতীয় জিনিস → পর্দায় pixel। [Ch 27]

পুরো যাত্রায় হয়তো তোমার handler-এর CPU-সময় মিলিসেকেন্ডেরও ভগ্নাংশ — বাকিটা kernel-এর কারিগরি আর অপেক্ষার শিল্প। এবার production-এর চেনা রোগগুলোও নতুন চোখে দেখো: latency spike? — DB-র disk নাকি event loop কেউ আটকে রেখেছে নাকি accept queue উপচে পড়ছে? Memory বাড়ছে? — heap leak নাকি কেউ receive buffer পড়ছে না? প্রতিটা প্রশ্ন এখন এই map-এর কোনো না কোনো জায়গায় pin করা যায়।

চূড়ান্ত উপলব্ধি

"Backend engineer" পদটার গোপন অর্থ: দুই kernel-এর মাঝখানে বসে orchestration করা মানুষ। তোমার code যত ভালো হোক, request-এর ভাগ্য নির্ধারণ করে buffers, queues, caches, syscalls আর scheduler — এখন থেকে এরা তোমার কাছে অদৃশ্য না।
