PART 12 · ENGINEERING INTUITION

Chapter 39 — Software ধীর হয় কেন

"Slow" একটা রোগের নাম না — উপসর্গ। এই chapter হলো রোগ নির্ণয়ের চেকলিস্ট।

প্রথম নিয়ম, খোদাই করে রাখো: আগে মাপো, তারপর ভাবো, সবার শেষে optimize করো। অনুমানের ভিত্তিতে optimization প্রায়ই ভুল জায়গায় শ্রম। এখন, "slow"-এর পিছনে সাধারণত এই সন্দেহভাজনদের কেউ থাকে:

সন্দেহভাজনচেনার উপায় (লক্ষণ)কোন chapter-এর জ্ঞান লাগবে
CPU-boundCore গুলো 100%-এ, তবু কাজ শেষ হয় না। top-এ user CPU বেশি।12-14, 19 — parallelism, cache-friendly algorithm
Memory-boundCPU "busy" দেখায় কিন্তু আসলে RAM-এর অপেক্ষায়; এলোমেলো বড় data structure, cache miss-এর মিছিল।7-8, 13 — locality, data layout
Memory pressure / swapসবকিছু হঠাৎ কাদায় হাঁটছে; vmstat-এ si/so নড়ছে, major fault বাড়ছে, OOM-এর গন্ধ।9-10 — working set vs RAM
Disk-boundCPU অলস, iowait উঁচু; ছোট random read-এর বন্যা, fsync-ভারী write।20-24 — cache, batching, sequential
Network-boundLatency-র সিংহভাগ বাইরের service-এ; N+1 query, chatty API।25-29 — round-trip কমাও
Too many threads / context switchingvmstat-এ cs আকাশে, throughput বাড়ে না বা কমে; CPU busy অথচ "কাজ" কম।17, 19 — worker সংখ্যা core-এ নামাও
Blocking / event loop jamP99 কুৎসিত কিন্তু গড় ভালো; Node-এ event loop lag metric বাড়ে।28-29 — sync কাজ loop থেকে বের করো
Excessive syscallsstrace -c-তে লাখো ক্ষুদ্র read/write; per-call overhead জমে পাহাড়।32 — batching, বড় buffer
Lock contentionCore বাড়ালেও speed বাড়ে না; সবাই এক lock/এক DB row-এর লাইনে।18 — critical section ছোট করো, ভাগ করো

খেয়াল করো — এই তালিকার একটা রোগও তোমার application-এর code দেখে ধরা যায় না; ধরা যায় OS-এর জানালা দিয়ে দেখলে (top, vmstat, iostat, strace, ss)। এই বইয়ের আসল উপহার এই জানালাগুলো চেনা।

সাবধান

কোনো magical checklist নেই — "cache যোগ করো / thread বাড়াও / SSD লাগাও" জাতীয় ঢালাও ওষুধ প্রায়ই রোগ না জেনে antibiotics। আগে কোন resource-এ আটকে আছো সেটা প্রমাণসহ বের করো; সমাধান তখন প্রায় নিজেই দেখা দেয়।
