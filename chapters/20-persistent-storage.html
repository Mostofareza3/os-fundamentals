PART 6 · STORAGE

Chapter 20 — Persistent Storage

RAM-এর বাইরের জগৎ — যেখানে data power গেলেও বাঁচে, কিন্তু দাম দিতে হয় speed-এ।

কেন persistence আলাদা সমস্যা

RAM volatile — তাই database, file, log সবকিছুর একটা "স্থায়ী ঠিকানা" লাগে। সেই ঠিকানাই storage। কিন্তু storage-এর economics সম্পূর্ণ আলাদা: RAM-এর চেয়ে অনেক সস্তা আর বড়, কিন্তু অনেক ধীর। এই gap-টাই file I/O-র পুরো design-কে shape করে।

Deviceকীভাবে কাজ করেCharacter

NVMe SSDFlash + PCIe দিয়ে সরাসরি CPU-র কাছেআজকের standard। বিশাল parallelism — একসাথে বহু request গিলতে পারে। তোমার Mac-এর ভিতরে এটাই।

Latency vs throughput — আলাদা করে ভাবো

  • Latency: একটা request-এর জবাব আসতে কত সময়। DB-র একটা ছোট read এখানে আটকায়।
  • Throughput: প্রতি second মোট কত data। বড় file copy/backup এখানে আটকায়।

দুটো আলাদা অক্ষ — একটা device-এর throughput দুর্দান্ত হয়েও latency মাঝারি হতে পারে। আর সব device-এই sequential access random-এর চেয়ে সুবিধাজনক (HDD-তে আকাশ-পাতাল, SSD-তেও লক্ষণীয়)। Database-রা এজন্যই append-only log (WAL) এত ভালোবাসে — লেখাগুলো sequential করে ফেলা।

মাত্রাজ্ঞান (মুখস্থ না, অনুপাত)

মোটা দাগে সিঁড়িটা এরকম — লাফগুলো সমান নয়, আর অসমতাটাই আসল খবর:

CPU cache   ~1 ns
RAM         ~100 ns      ← ×১০০
NVMe        ~50–100 µs   ← ×~৫০০  (সিঁড়ির সবচেয়ে বড় লাফ)
HDD         ~10 ms       ← ×~১০০

মানে RAM-এ যা চোখের পলক, disk-এ তা দুপুরের খাবার-বিরতি। বিশেষ করে RAM → NVMe লাফটা খেয়াল করো — এটা এক-দুই মাত্রা না, তিন মাত্রার কাছাকাছি। এটাই বোঝায় কেন OS এত মরিয়া হয়ে disk access এড়াতে চায় (Chapter 23-এর page cache)।

Network storage-কে ইচ্ছা করেই সিঁড়ির শেষে বসাইনি, কারণ তার কোনো স্থির ধাপ নেই — same-AZ-এ ভালো provisioned network SSD (EBS, NVMe-oF) প্রায়ই ১ ms-এর নিচে জবাব দেয়, অর্থাৎ local HDD-র চেয়ে দ্রুত। আর WAN-এর ওপাশে বসা storage শত ms-ও নিতে পারে। "Network মানেই সবচেয়ে ধীর" — এই intuition টা ভুল সিদ্ধান্ত আনে; দূরত্ব আর provisioning দেখে বিচার করতে হয়।
