PART 3 · MEMORY

Chapter 8 — CPU আর Memory-র কথাবার্তা

একটা memory access-এর ভিতরের যাত্রাপথ — cache-এর foundation এখানেই।

একটা load instruction-এর যাত্রা

ধরো CPU-র সামনে instruction: "address X থেকে value আনো" (load)। ঘটনা broadly এরকম:

CPU: "address X-এর data চাই"
  ↓
1. L1 cache-এ আছে?  ── হ্যাঁ → নিয়ে নাও  (দ্রুততম)
  ↓ না
2. L2 cache-এ আছে?  ── হ্যাঁ → নিয়ে নাও
  ↓ না
3. L3 cache-এ আছে?  ── হ্যাঁ → নিয়ে নাও
  ↓ না
4. RAM থেকে আনো    (সবচেয়ে ধীর ধাপ — শত শত cycle)
  └─ আনার সময় data-টা cache-এও রেখে দাও, পরেরবারের জন্য

মূল idea: CPU সরাসরি RAM-এ যায় না। মাঝে ছোট, দ্রুত memory-র কয়েকটা স্তর আছে — cache hierarchy। সম্প্রতি ব্যবহৃত data cache-এ থাকে; পাওয়া গেলে cache hit (সস্তা), না পেলে cache miss (দামি — RAM পর্যন্ত যাত্রা)।

MENTAL MODEL

Memory access-এর cost একটা fixed number না — এটা একটা lottery: data কোথায় বসে আছে তার উপর নির্ভর করে একই instruction সস্তাও হতে পারে, শতগুণ দামিও হতে পারে। Performance-sensitive code লেখার সময় আসল খেলা হলো এই lottery-তে জেতার সম্ভাবনা বাড়ানো — মানে cache-friendly access pattern। কীভাবে, সেটা Chapter 13-এ।

আরেকটা সূক্ষ্ম কথা: CPU byte ধরে ধরে RAM থেকে আনে না — আনে cache line ধরে (সাধারণত 64 bytes-এর chunk)। মানে address X চাইলে তার আশেপাশের byte গুলোও ফাউ হিসেবে cache-এ চলে আসে। এই এক তথ্যই sequential vs random access-এর পুরো পার্থক্যের বীজ — মাথায় রেখো।
