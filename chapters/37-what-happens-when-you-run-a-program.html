PART 11 · PUTTING EVERYTHING TOGETHER

Chapter 37 — একটা Program চালালে কী কী ঘটে?

পুরো বইয়ের প্রথম মহাসংযোগ। Terminal-এ লিখলে ./app আর Enter চাপলে —

  1. Shell পড়লো তোমার লাইন — সে নিজেও এক সাধারণ process, stdin-এ read() করে বসে ছিল (Waiting-এ)। তোমার Enter-এ keyboard-এর interrupt → kernel → shell জাগলো। [Ch 15, 31]
  2. Executable খোঁজা — PATH-এর directory-গুলোতে; প্রতিটা খোঁজ মানে filesystem-এ path resolution। [Ch 22]
  3. fork() — shell নিজের copy বানালো; copy-on-write-এ প্রায় বিনা খরচে। [Ch 15, 9]
  4. exec() — child-এর ভিতরে নতুন program: ELF header পড়া, নতুন virtual address space, code/data mmap (কিন্তু lazy!), stack-এ argv, dynamic linker-এর library জোড়া, PC → entry point। [Ch 34, 33, 5]
  5. প্রথম instruction-এই page fault! — code-এর page টা তো এখনো disk-এ। Kernel: filesystem → block layer → driver → device → DMA → page cache → page table update → আবার চালাও। প্রথম কিছু মুহূর্ত এভাবে fault-এ fault-এ program-টা "টুকরো টুকরো জন্মায়"। [Ch 9, 21, 11]
  6. এবার আসল দৌড় — fetch-decode-execute-এর কোটি কোটি চক্কর; কখনো cache hit-এর সুখ, কখনো miss-এর RAM-যাত্রা, TLB-র নীরব অনুবাদ প্রতি access-এ। [Ch 12, 13, 9]
  7. Program কিছু চাইলো — file পড়া? read() syscall → kernel → (ভাগ্য ভালো হলে page cache hit) → data। Network? socket path। প্রতিটা চাওয়ায় নীল-থেকে-amber-থেকে-নীল সেই যাত্রা। [Ch 21, 25-27, 31-32]
  8. মাঝে মাঝে সে-ও থামলো — I/O-র wait-এ Blocked, বা timer interrupt-এ scheduler-এর preemption; তার context save, অন্য কারো restore — machine-জুড়ে চলা হাজারো process-এর নাচের এক পা মাত্র সে। [Ch 15, 17]
  9. Output — তোমার terminal-এ লেখাও আসলে write() — terminal-ও এক file descriptor! [Ch 21, 25]
  10. exit() — শেষ syscall। Kernel memory ফেরত নিলো, fd গুলো বন্ধ করলো, exit code রেখে দিলো — shell (parent) wait() করে সেটা তুললো, prompt ফিরিয়ে দিলো। [Ch 15]
এখন পরীক্ষা করো নিজেকে

উপরের দশটা ধাপ বই বন্ধ করে, নিজের ভাষায়, কাউকে (বা রাবার হাঁসকে) বলে যাও — কোথায় আটকাও দেখো। যেখানে আটকাবে, সংশ্লিষ্ট chapter-টাই তোমার revision list। এই এক গল্প ঝরঝরে বলতে পারা মানে বইয়ের ৮০% হজম।
