PART 5 · PROCESS MANAGEMENT

Chapter 17 — Context Switching

৪টা core-এ ৪০০টা process "একসাথে" চলার জাদু — আর সেই জাদুর দাম।

Context মানে কী

Chapter 12-র সেই বাক্যটা ফিরিয়ে আনি: একটা thread-এর execution state মানে registers + program counter + stack pointer-এর snapshot। এটাই তার context — "আমি কোন instruction-এ ছিলাম, আমার হিসাবের মাঝপথের value গুলো কী, আমার stack কোথায়।"

Switch-টা কীভাবে ঘটে

Process A চলছে...
   ↓ interrupt (timer) বা A নিজেই block হলো (I/O চাইলো)
━━━━━━ kernel mode-এ প্রবেশ ━━━━━━
1. A-র context (registers, PC, SP) kernel-এ save
2. Scheduler: "এরপর কে?" → B নির্বাচিত
3. Address space switch — B-র page table চালু
4. B-র সেভ-করা context registers-এ restore
━━━━━━ user mode-এ ফেরা ━━━━━━
Process B ঠিক সেখান থেকে চলা শুরু করলো,
যেখানে সে শেষবার থেমেছিল — যেন কিছুই হয়নি

Switch trigger হয় মূলত দুইভাবে: (১) process নিজে block হলো — I/O, sleep, lock-এর অপেক্ষা; (২) kernel জোর করে থামালো — timer interrupt-এ scheduler দেখলো অনেকক্ষণ চলেছে, এবার অন্যের পালা (preemption)। এই দ্বিতীয়টার জন্যই একটা infinite loop-ওয়ালা process পুরো machine জমিয়ে ফেলতে পারে না।

দামটা কোথায়

Context switch free না — কিন্তু দামটা যেখানে ভাবো সেখানে না। Register save/restore নিজে সস্তা। আসল খরচ:

  • Kernel-এ ঢোকা-বেরোনো — mode switch-এর overhead।
  • Cache দূষণ: A-র data দিয়ে গরম হয়ে থাকা CPU cache B-র কোনো কাজে লাগে না; B-র শুরুটা হয় ঠান্ডা cache-এ — miss-এর ঝড়। A ফিরে এলে তার cache-ও ততক্ষণে B-র data-য় ভরে গেছে।
  • TLB flush: Address space বদলালে পুরনো translation গুলোও অচল।

মানে switch-এর পরের কিছু সময় ধরে সবকিছুই একটু ধীর চলে। Exact nanosecond মুখস্থের দরকার নেই — takeaway হলো: switch যত ঘনঘন, "আসল কাজ"-এর ভাগ তত কম। হাজার হাজার thread বানিয়ে ফেললে CPU সময়ের বড় অংশ যায় জায়গা বদলাবদলিতেই — এই রোগের নাম thrashing। (এক process-এর দুই thread-এর মধ্যে switch একটু সস্তা — address space বদলায় না — কিন্তু cache-এর সমস্যা থেকেই যায়।)

MENTAL MODEL

CPU হলো এমন এক পাঠক যে হাজারটা বই "একসাথে" পড়ছে — প্রতিটা বইয়ে bookmark (context) রেখে রেখে লাফাচ্ছে। লাফানো এত দ্রুত যে মনে হয় সব বই একসাথে পড়া হচ্ছে। কিন্তু প্রতিটা লাফে bookmark রাখা-খোঁজা + "কোথায় যেন ছিলাম" মনে করার (cache warm-up) খরচ আছে।

EXPERIMENT (Linux)

vmstat 1 চালাও — cs column দেখায় প্রতি second context switch-এর সংখ্যা। একটা idle machine-এও হাজারে হাজারে দেখতে পারো। তারপর কোনো busy কাজ চালিয়ে দেখো সংখ্যাটা কীভাবে নড়ে।
