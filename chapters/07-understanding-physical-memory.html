PART 3 · MEMORY

Chapter 7 — Physical Memory বোঝা

RAM আসলে কী, আর কেন সেটা যত fast ভাবো তত fast না।

RAM কী

RAM (Random Access Memory) হলো সেই hardware যেখানে চলমান process-দের code আর data থাকে। "Random access" মানে যেকোনো address-এ প্রায় সমান সময়ে পৌঁছানো যায় — disk-এর মতো ঘুরে ঘুরে খুঁজতে হয় না। আর RAM volatile — power গেলে সব মুছে যায়। এজন্যই "save" বলে একটা জিনিস আছে: RAM থেকে persistent storage-এ নেওয়া।

Physically RAM থাকে DIMM module-এ (motherboard-এর ওই লম্বা stick গুলো), আর আজকের প্রযুক্তির নাম DDR (DDR4/DDR5)। আমাদের জন্য এটুকু জানাই যথেষ্ট — এই বই memory hardware-এর encyclopedia না।

Physical address

RAM-কে ভাবো একটা বিশাল byte-এর array। প্রতিটা byte-এর একটা নাম্বার আছে — physical address। 16GB RAM মানে মোটামুটি 0 থেকে ১৬০০ কোটি+ পর্যন্ত address। CPU যখন memory access করে, শেষ পর্যন্ত এই physical address-ই ব্যবহৃত হয়। (কিন্তু তোমার process এই address কখনো সরাসরি দেখে না — সেই twist Chapter 9-এ।)

Memory infinitely fast না কেন

এখানেই একটা অস্বস্তিকর সত্য: CPU-র তুলনায় RAM ধীর। আধুনিক CPU প্রতি nanosecond-এ একাধিক instruction চালাতে পারে, কিন্তু RAM থেকে একটা data আনতে লাগে দশগুণ-শতগুণ বেশি সময় (exact number hardware-ভেদে ভিন্ন, তাই মুখস্থ করার দরকার নেই — অনুপাতটাই আসল)। কারণটা physics + engineering: RAM chip CPU থেকে physically দূরে, signal যেতে-আসতে সময় লাগে, আর DRAM cell পড়ার নিজস্ব latency আছে।

MENTAL MODEL

CPU হলো একটা দ্রুতগতির chef, RAM হলো storeroom। Chef-এর হাত যত দ্রুতই চলুক, প্রতিটা উপকরণের জন্য storeroom-এ হেঁটে গেলে রান্নার speed storeroom-এর হাঁটাপথেই আটকে যাবে। এই gap-টার নাম চলতি ভাষায় "memory wall" — আর এটা মেটানোর জন্যই cache-এর জন্ম (Chapter 8, 13)।

EXPERIMENT

Linux-এ free -h চালাও। used, free, আর buff/cache column গুলো দেখো। অবাক লাগতে পারে যে "free" এত কম — আসলে OS ইচ্ছা করেই অলস RAM-কে file cache হিসেবে ব্যবহার করে (Chapter 23-এ বুঝবে কেন এটা ভালো জিনিস)। available column-টাই আসল "কতটুকু পাওয়া যাবে"-র হিসাব।
