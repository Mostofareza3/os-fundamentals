Chapter 2 — The System Architecture

সব component-এর relationship একটা map-এ, আর একটা end-to-end উদাহরণ।

Player-দের চিনে নেই

Componentএক লাইনে কাজ
CPUInstruction execute করে। একমাত্র জায়গা যেখানে "কাজ" হয়।
RAM (Memory)Running process-এর code আর data রাখে। Fast, কিন্তু volatile — power গেলে সব শেষ।
Storage (SSD/HDD)Persistent data। Slow (RAM-এর তুলনায়), কিন্তু power গেলেও থাকে।
Network devicePacket পাঠায়/রিসিভ করে।
ProgramDisk-এ পড়ে থাকা executable file। Passive জিনিস।
ProcessRunning program — নিজস্ব memory, নিজস্ব state সহ। Active জিনিস।
KernelResource manager। সবসময় memory-তে থাকে।
DriverKernel-এর ভিতরের সেই code যেটা specific hardware-এর ভাষা জানে।
File systemRaw disk block-কে file/directory হিসেবে organize করে।
System callUser space → kernel space-এ ঢোকার একমাত্র official দরজা।

End-to-end example: একটা file read

ধরো তোমার Node.js code লিখলো fs.readFileSync("config.json")। Broadly যা ঘটে:

1. Application:  readFileSync("config.json") call করলো
2. Runtime/libc: ভিতরে গিয়ে read() system call বানালো
━━━━━━━━━━ user → kernel mode switch ━━━━━━━━━━
3. Kernel:       request receive করলো
4. File system:  "config.json" মানে disk-এর কোন block? বের করলো
5. Page cache:   data আগেই cache-এ আছে কি? (থাকলে shortcut!)
6. Block layer:  না থাকলে disk-এর জন্য read request queue করলো
7. Driver:       storage device-কে command পাঠালো
8. Device:       data পড়ে DMA দিয়ে memory-তে দিলো
9. Kernel:       data process-এর buffer-এ copy করলো
━━━━━━━━━━ kernel → user mode switch ━━━━━━━━━━
10. Application: data হাতে পেলো, কাজ চললো

প্রতিটা step এখনই পুরোপুরি বোঝার দরকার নেই — page cache, DMA, block layer সব সামনের chapter-গুলোতে আসবে। এখন শুধু structure-টা মাথায় গাঁথো: application কখনো disk-কে সরাসরি দেখে না। মাঝখানে সবসময় kernel থাকে।

MENTAL MODEL

যেকোনো I/O-এর গল্প আসলে একই pattern: user space request → system call → kernel-এর layer গুলো → hardware → ফেরার পথ উল্টো। File হোক, network হোক — pattern এক, শুধু মাঝের layer বদলায়।

COMMON MISCONCEPTION

"OS মানে UI — desktop, window, icon।" না। Desktop environment একটা application মাত্র। আসল OS হলো kernel + তার service গুলো, যেটা server-এ UI ছাড়াই দিব্যি চলে। তুমি যে production server-এ deploy করো, সেখানে OS পুরোদমে কাজ করছে — কোনো UI ছাড়াই।
