PART 6 · STORAGE

Chapter 23 — Page Cache

Memory আর storage-এর জগৎ যেখানে মিলে যায় — এবং তোমার "দ্বিতীয়বার fast" রহস্যের সমাধান।

Idea

Disk RAM-এর চেয়ে মাত্রায়-মাত্রায় ধীর (Chapter 20)। আর RAM-এর খালি অংশ এমনিতেই বসে থাকে। Kernel-এর সিদ্ধান্ত: disk থেকে যা-ই পড়া হোক, RAM-এ রেখে দাও — কে জানে আবার লাগবে। এই জায়গাটার নাম page cache — file data-র page-size টুকরো, RAM-এ, kernel-এর জিম্মায়।

এজন্যই free -h-তে "buff/cache" এত বড় (Chapter 7-এর সেই ধাঁধা!) — এটা "দখল" না, এটা service। কোনো process-এর memory লাগলে kernel cache ছেড়ে দেয় — clean page ফেলে দেওয়া তো free।

Read path আর write path

READ:  read() → page cache-এ আছে? ── hit → copy, শেষ। (RAM speed!)
                    └── miss → disk থেকে এনে cache-এ রাখো → copy

WRITE: write() → cache-এর page-এ লেখো → page টা dirty → return!
                    ...পরে background-এ kernel dirty page গুলো disk-এ নামায়

Dirty page মানে: cache-এর version disk-এর চেয়ে নতুন। Kernel এগুলো সময়মতো/চাপে পড়ে flush করে; fsync মানে "এই file-এর dirty page গুলো এক্ষুনি নামাও" (Chapter 21-এর সেই গল্প)। "চাপে পড়ে"-র একটা সীমা আছে — dirty page RAM-এর একটা অনুপাত (dirty_ratio) ছাড়িয়ে গেলে kernel লেখক process-টাকেই write()-এ আটকে দেয় যতক্ষণ না writeback ধরে ফেলে। এজন্যই মাঝেমধ্যে "write() তো block করে না" বলা সেই call-টাই হঠাৎ সেকেন্ড খেয়ে ফেলে।

ফলাফল: চেনা চেনা কিছু behavior-এর ব্যাখ্যা

  • একই file দ্বিতীয়বার পড়া নাটকীয়ভাবে fast — প্রথমবার disk, দ্বিতীয়বার RAM। Benchmark করার সময় এটা মাথায় না রাখলে ভুল সিদ্ধান্তে পৌঁছাবে ("cold cache vs warm cache")।
  • Database server-এ "free RAM" প্রায় শূন্য দেখায় — এবং সেটাই কাম্য: পুরো RAM জুড়ে data file-এর cache।
  • Server restart-এর পর প্রথম কিছুক্ষণ সব ধীর — cache ঠান্ডা, ধীরে ধীরে গরম হয়।
MENTAL MODEL

এতক্ষণে খেয়াল করেছ নিশ্চয়ই — এই গল্পটা আগে শুনেছ: CPU-র জন্য cache (Chapter 13), address translation-এর জন্য TLB (Chapter 9), আর disk-এর জন্য page cache। যেখানেই দুই স্তরের speed-এ বিশাল ফারাক, মাঝখানে একটা cache — computing-এর সবচেয়ে পুনরাবৃত্ত design pattern। তোমার Redis layer-ও একই pattern-এর আরেক তলা।

EXPERIMENT (Linux)

একটা বড় file নাও (না থাকলে বানাও: dd if=/dev/zero of=big.bin bs=1M count=500)। তারপর: time cat big.bin > /dev/null — দুইবার চালাও। দ্বিতীয়বারের সময়টা দেখো। এটাই page cache, খালি চোখে।
