এই বই কার জন্য

ধরে নিচ্ছি তুমি একজন working software engineer: JavaScript/TypeScript-এ স্বচ্ছন্দ, terminal-এ সাধারণ কাজ পারো, কিন্তু OS-এর ভেতরটা কখনো গুছিয়ে দেখা হয়নি। C বা pointer জানার দরকার নেই; C আসে শুধু Chapter 33–34-এ, compile আর link দেখানোর জন্য, তাও কয়েক লাইনের। Process, thread, virtual memory, socket — শব্দগুলো শুনেছ, কিন্তু এরা একে অন্যের সাথে কীভাবে জোড়া, সেই ছবিটা এখনো মাথায় দাঁড়ায়নি।

এই বই academic OS course না। Scheduling algorithm-এর exam question বা deadlock-এর mathematical proof এখানে পাবে না। পাবে একটা জিনিস — তোমার application-এর নিচে OS আসলে কী করছে, এবং সেটা তোমার code-এর performance আর behavior-এ কীভাবে impact ফেলে।

এই বইয়ের backbone: একটাই গল্প

পুরো বই এই এক গল্প, সাত ধাপে। নীল ধাপে তোমার code, amber ধাপে kernel, রং ছাড়া ধাপে hardware। ডানে প্রতিটা ধাপের chapter।

৪০টা chapter আসলে এই এক গল্পেরই আলাদা আলাদা zoom level। Chapter 37 আর 38-এ গিয়ে পুরোটা একসাথে জোড়া লাগবে, সত্যিকারের trace ধরে।

কীভাবে পড়বে

  • Sequence maintain করো। Chapter গুলো একটার উপর আরেকটা build করে। Virtual memory না বুঝে page cache বুঝবে না।
  • Experiment গুলো সত্যি চালাও। প্রায় প্রতিটা ধারণার সাথে একটা ছোট Node বা Linux experiment আছে। Mac-এ যেগুলো চলে সেগুলো সরাসরি; Linux-এর জিনিস (strace, tcpdump, cgroup) Docker-এর ভেতরে, পুরো command-সহ। বইয়ের output আমার machine-এর (M4 Pro Mac আর তার Docker VM)। তোমার সংখ্যা আলাদা হবে, কিন্তু মাত্রা আর ধাপগুলো মিলবে।
  • "Can I explain this?" গুলো skip কোরো না। নিজের ভাষায় explain করতে না পারলে বোঝা হয়নি — শুধু term চেনা হয়েছে।
