PART 2 · FROM PROGRAM TO PROCESS

Chapter 4 — Program কীভাবে execute হয়

Source code থেকে চলমান process পর্যন্ত পুরো pipeline — high level-এ।

Source থেকে executable

একটা ছোট C program ধরি (C এখানে শুধু tool — OS-এর সবচেয়ে কাছের ভাষা বলে):

#include <stdio.h>

int main() {
    printf("hello\n");
    return 0;
}

gcc hello.c -o hello চালালে ভিতরে কয়েকটা ধাপ ঘটে:

hello.c (source)
   ↓ compiler — C কে assembly/machine code-এ translate
hello.o (object file — machine code, কিন্তু অসম্পূর্ণ)
   ↓ linker — printf-এর মতো বাইরের function-এর ঠিকানা জোড়া লাগায়
hello (executable — ELF file, run করার জন্য ready)

Object file "অসম্পূর্ণ" কেন? কারণ তোমার code printf call করেছে, কিন্তু printf-এর code তোমার file-এ নেই — সেটা C library-তে। Linker-এর কাজ এই reference গুলো resolve করা। (Static vs dynamic linking Chapter 33-এ।)

ELF: executable-এর গঠন

Linux executable-এর format হলো ELF (Executable and Linkable Format)। ভিতরে মোটা দাগে থাকে: header (এটা কী ধরনের file, execution কোথা থেকে শুরু — entry point), machine code section, initialized data section, আর dynamic library-র dependency list। JavaScript developer হিসেবে ভাবতে পারো — ELF হলো compiled program-এর package.json + bundle একসাথে।

Run করার মুহূর্তে: loader

./hello চালালে shell একটা system call দিয়ে kernel-কে বলে "এই executable থেকে process বানাও"। তখন kernel-এর loader অংশ কাজ করে:

  1. নতুন process তৈরি করে (PID, address space)
  2. ELF header পড়ে code আর data segment গুলো process-এর memory-তে map করে
  3. Stack setup করে (argv, envp বসায়)
  4. CPU-র program counter (instruction pointer)-কে entry point-এ set করে দেয়

ব্যস — এখন CPU ওই address থেকে instruction fetch করে execute করা শুরু করে। Program "চলছে" মানে আসলে এটুকুই: CPU-র program counter তোমার code-এর ভিতর দিয়ে হাঁটছে।

একটা সূক্ষ্মতা: dynamic library গুলো kernel load করে না। Binary টা dynamically linked হলে kernel প্রথম লাফ দেয় dynamic linker (ld.so)-এর entry point-এ — সেটা user space-এ চলা একটা program, আর সে-ই .so গুলো map করে, তারপর তোমার code-এ control ছাড়ে। মানে process-এর প্রথম user-space instruction টা আসলে তোমার না। বিস্তারিত Chapter 34-এ।

তাহলে JavaScript/Python-এর বেলায়?

node server.js চালালে process টা আসলে node executable-এর — সেটাই ELF, সেটাই load হয়। তোমার server.js হলো ওই process-এর data, যেটা V8 engine পড়ে ভিতরে JIT compile করে চালায়। OS-এর চোখে process একটাই — node। এজন্যই ps দিলে দেখো "node", "server.js" না।
